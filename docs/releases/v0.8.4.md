# Lightning 0.8.4

A composing-and-managing release. The last few rounds went into calls; this
one goes into the parts of a chat client you use between them. The headline is
that **the message box can format text now** — bold, italic, lists, quotes,
code and spoilers, with slash commands and a spell checker — and that a room's
own settings, its access rules and even its room version are editable from
inside the client instead of from Element.

It also renames the installed binary. See the note at the end.

## A composer that can format

The message box is a rich editor. Bold, italic, strikethrough, inline code,
code blocks, block quotes, bulleted and numbered lists, links, and spoilers.
Keyboard shortcuts work the way they do everywhere else, and the toolbar
carries the same set for people who would rather click.

What is sent is a normal Matrix formatted message: an HTML body beside the
plain-text one, so a client that cannot render it still shows something
readable rather than markup. Inbound HTML goes through the SDK's sanitizer
before it reaches the renderer, in both directions, and the plain-text
fallback is generated rather than guessed at.

Spoilers are the MSC2010 shape Element uses, so a spoiler written here is
hidden in Element and the other way round.

The composer keeps its formatting per room, and in a thread it sends through
the thread-focused path, never as an ordinary room message.

## Slash commands

Type `/` for a list. The popup filters as you type, scrolls when the list is
longer than the box, and Enter runs the highlighted one.

They dispatch real events, so each is treated as a real action: an argument
that cannot be parsed refuses rather than sending something approximate.

## Spell checking

Both composers underline misspelled words, with the platform's own dictionary
and the platform's own personal word list:

* **Linux and BSD** use enchant, the same broker KDE, GNOME, LibreOffice and
  Firefox use, so it finds the dictionaries your distribution already has and
  writes to your own `~/.config/enchant`. It is loaded with `dlopen` at
  runtime, so a machine without enchant reports honestly that spell checking
  is unavailable instead of failing to start.
* **Windows** uses the Windows 8+ spell-check service and your own Windows
  custom dictionary.
* **macOS** uses `NSSpellChecker`, including "Learn Spelling".

No dictionary is bundled and nothing about a draft leaves the machine. Qt
ships no spell checker of its own, so the engine had to be supplied; every one
of these is local.

A chat message is full of things that are correct by not being English, so
room aliases, Matrix IDs, URLs, code spans, emoji shortcodes, ALL-CAPS runs and
the word the caret is still inside are never underlined. The language is
Automatic by default and can be pinned in Settings.

**Debian and Ubuntu:** the package recommends `libenchant-2-2`, which apt
installs by default. If you installed with `--no-install-recommends`, install
it to get spell checking.

## Room settings, access, and room upgrades

A room's name, topic, avatar, join rule, guest access and history visibility
are editable from the client, and so is the room version.

Upgrading a room creates a new room and tombstones the old one, which cannot
be undone, so it is behind a confirmation that says exactly that. The
version list comes from the homeserver's own `/capabilities` rather than a
table compiled into the client, and the button is offered only when the
server says you have the power level for it.

## Edit history and view source

Any edited message can show what it said before, fetched from the server
rather than from whatever this client happened to have loaded. When the
server can only answer partially, it is presented as partial rather than as
the whole story.

View source shows the event as the server sees it, for anyone debugging a
room. It carries no tokens, no keys and no authenticated media URLs.

## Send later

Write a message now and have it delivered at a chosen time.

Where the homeserver supports MSC4140 delayed events, the server holds it, so
it goes out whether or not Lightning is running. Where the server does not,
Lightning holds it and sends it while running, and says which of the two you
are getting rather than implying the stronger one. Note that Synapse ships
MSC4140 **off** by default.

A scheduled message for an encrypted room is held in memory only and is never
written to disk.

## An Activity Center

One place for everything addressed to you across every room: mentions, room
mentions, replies, thread replies, reactions to your messages, invites, and
your own keyword matches. It has its own read marker, separate from any
room's.

## Session names, key backup, and a status message

Sessions can be renamed, so a device list reads like your devices instead of
like a list of IDs. Key backup state is visible and manageable from Settings.
Nothing there implements any cryptography of its own: every trust label comes
from the SDK, and importing keys still does not mark a device verified.

A short status message can sit beside your presence.

## Smaller things

* A day's activity sits under its own date separator.
* Conversation lists are ordered by activity rather than by category.
* Bridged conversations are labelled by network, and a bridged DM is named
  after the person rather than after the plumbing.
* Link previews load through your homeserver first and go direct only as a
  fallback.
* Sign-in follows `.well-known` Matrix delegation.
* A browser that fails to launch during OAuth sign-in is reported instead of
  failing silently.
* Reaction chips match Element's size, and no glyph can change one's shape.
* The window is placed once at startup instead of re-centring itself.
* A rail tile's unread badge counts what that tile's own view lists.
* A room that cannot fill its viewport stops asking for more history, and
  several pagination budget fixes beside it.
* A Nix flake package and a home-manager module.
* **Lithuanian**, and every one of the eleven translation catalogs refreshed,
  with a CI gate that now fails a build whose catalogs have fallen behind the
  source.

## Fonts and image formats

A font that cannot actually draw Latin text is no longer offered in the font
pickers. Emoji faces report themselves as fixed-pitch, so they were being
listed as monospace choices and produced unreadable digits when picked.

Every Linux package now carries the image plugins the client's own byte
sniffers accept, which they did not before: **WebP** is a hard dependency on
the deb and rpm, and **JPEG XL** is staged from KDE's kimageformats. Until
now the client would accept and forward a WebP image it could not draw. Each
package format is checked after it is built by asking the shipped binary
whether the decoders actually register, rather than by looking for the files.

## The binary is now `lightning-matrix`

The installed executable and the CMake target were called `matrix-client`,
which is a generic name for a program that has one. Both are now
`lightning-matrix`, matching what the application has been called everywhere
else since 0.6.

If you launch Lightning from a menu, a `.desktop` entry or the AppImage, this
changes nothing. If you launch it from a script or a terminal by name, update
the name.

## Validation

Complete Rust tests plus Rust and non-Rust builds and CTest were run against
the release commit, and the tree also builds with the media engine disabled,
which is the configuration the Linux package jobs use.

Everything above was also put through an independent pre-release audit before
this release was cut, and that audit found real defects in code that had
already passed its own tests. All of them are fixed here; they are listed
because the shape of them is more useful than the fact of them:

* **"Upgrade space…" would have upgraded the wrong room.** The upgrade
  controller tracks the *active* room, because the tombstone banner sits above
  the open timeline — but Space settings opens as a modal *over* that room
  without navigating. So confirming an upgrade there would have irreversibly
  tombstoned the room behind the dialog while the confirmation displayed the
  space's name and version. The target is now an explicit argument that the
  caller must name and the controller refuses to guess.
* **A scheduled message for an encrypted room could reach disk.** The server
  answers "I cannot hold an encrypted message" and the client used that answer
  to change how the message was sent while ignoring it for where the message
  was stored. That answer is now authoritative for both.
* **Five labels rendered unsanitized server text as rich text.** A QML label
  defaults to auto-detecting HTML, so a room topic or a room name containing
  an image tag would have made every viewer's client fetch an attacker-chosen
  URL — including from an unsolicited invite, with no acceptance needed. All
  five are plain text now and a contract test pins them.
* **"Send now" on a server-held message could deliver it twice**, by
  discarding the server's handle when it could not reach the server, while the
  homeserver still sent the original at its deadline.
* **A slash command with any formatting applied was posted as a message.**
  Bolding one word of `/spoiler the ending is X` published the sentence to the
  room instead of hiding it. Commands are now recognised before formatting is
  considered.
* **An attachment with no text was silently dropped** in rich-text mode: the
  Send button was enabled, the click was accepted, and nothing was sent.
* **Edit history claimed to be complete when it was not**, and the Activity
  Center labelled every server-seeded row "Mentioned you" when the server had
  only said the row was highlighted.

**NOT TESTED** live: every feature in this release. The composer and header
fixes late in the round were reported from real use and re-checked by the
maintainer, but the nine features above have automated coverage only. In
particular no room upgrade, no scheduled send and no key-backup operation has
been performed against a real homeserver by this round, and none of the new
surfaces has been checked against Element for interoperability.

Windows and macOS packages remain unsigned. The signed update manifest is the
integrity guarantee on every platform.
