# Lightning 0.9.5

The Snap has never been able to make a call. Not "since a regression" — never,
in any version it has shipped in. This release is mostly about finding out
why, and about a handful of things that were quietly wrong in the parts of the
client that handle your encryption keys.

## The Snap works now

If you installed Lightning 0.9.4 as a Snap, it did not start. It aborted
before it could draw a window, and the three reasons were all the same kind of
reason: under strict confinement, `/usr` belongs to the base snap rather than
to your system, so anything Lightning expected to find there was simply not
there. No keyboard layouts, no font configuration, no graphics driver, and the
compositor socket one directory up from where it looked.

That is fixed, and so is something older and stranger underneath it.

Once the Snap could start, calls connected, published a track, distributed a
media key, negotiated correctly — and carried no audio in either direction.
The reason turned out to be a library loading its own plugins. Lightning's
SRTP encryption is built against NSS, and NSS does no cryptography itself: it
opens a separate module at runtime, by a path it works out while running. No
dependency list mentions it, so nothing bundled it. On an ordinary desktop
nobody would ever notice, because the system's own copy is found instead — but
a confined Snap has no system copy to fall back on, so the encryption layer
could not start and every call was silent.

The AppImage had the same gap. It worked only because your machine almost
certainly has NSS installed for its browser, and one that did not would have
failed in exactly the same way.

## Calls

**A shared window that never repaints now actually gets shared.** Sharing a
window that sits still — a file manager, a document you are not editing —
published nothing at all, and the person you shared it with waited forever on
"Waiting for the picture". Screen capture only delivers a frame when something
changes, and the encoder was waiting for a second frame that a motionless
window never produces.

**Only the newest call row offers "Join".** While a call was running, every
"started a call" row in that room's history grew a Join button, including ones
from days earlier.

**Calls no longer drop after five minutes.** A Lightning participant would
vanish from a call at almost exactly five minutes and come back — and while
they were gone they could still be heard but could hear nobody. The membership
that keeps you in a call was being refreshed on time with a value that could
not extend anything. This was fixed some time ago; this is the first release
where it has been held on a real call for nineteen minutes to prove it.

**On Windows**, the camera ran at ten frames a second because a plugin that
lets it negotiate a faster format was missing from the build; it now runs at
thirty. A remote screen share drew an empty rectangle on machines where
Lightning had picked the wrong renderer. Notifications work at all, which on
Windows they previously did not.

Also: hanging up from the floating call window, the participant strip clipping
itself, a machine with no usable graphics showing an empty rectangle instead
of saying so, and a stale "ghost" membership that could hide the way back into
a call.

## Encryption keys, recovery and backup

This is the part of Lightning that has never been tested by using it, because
doing that puts a freshly generated recovery key on screen and into any
screenshot. So before this release it was audited by reading it instead, from
the button all the way down into the Matrix SDK. Six things were wrong, and
two of them could destroy your ability to recover an account.

**Setting up recovery left the button that destroys it on screen.** After
"Set up recovery and backup" succeeded and showed you your key, the card still
said no backup existed and the button was still there. Press it again — which
is a reasonable thing to do when the screen says it did not work — and the key
you had just written down stopped working.

**"New recovery key" was offered on sessions that could not honour it.** On a
device that had not been verified, pressing it replaced your account's
recovery with one that unlocks nothing, and the old key stopped working. It is
now only offered where it can do what it says.

**A failed check no longer reads as a pass.** If Lightning could not fetch your
list of sessions, the security panel showed every check complete — claiming
all your devices were verified when it had not managed to ask.

Also fixed: an error message that said "nothing was changed" when something
usually had been; a recovery key that stayed in memory after the screen
promised it would not; an armed "Delete backup" confirmation that survived
closing Settings, so the second press that was meant to confirm it could
arrive an hour later; and a security prompt that sent you to the wrong
settings page for two of the three situations it appears in.

The verification flows — the emoji comparison, the QR code, signing in from
another device — were audited in the same pass and came out clean.

## Smaller things

A new **Sound & video** section in Settings, with device pickers and a
microphone level that you can check actually reaches the audio engine. **Seven
new keyboard shortcuts** for calls and navigation, all rebindable. The
**Activity Center** no longer shows raw `@user:server` identifiers where every
other part of the app shows a name. Settings stopped contradicting itself
about whether it had checked for updates. The sign-in field asks for a
username, because a username is what it takes.

## What this release does not do

Lightning is alpha software and this list is part of the release, not a
footnote to it.

**macOS is effectively untested.** It builds and it is published, and nobody
has sat down and used it.

**Screen sharing and the camera are untested on the Snap**, for an unglamorous
reason: the machine they were tested on has no desktop portal for a confined
application to talk to.

**Nobody has listened to a call.** Audio is proven to flow in both directions
and to reach the audio engine — no human has confirmed it sounds like
anything.

**Recovery and key backup are still not tested by use**, only by reading. The
defects above were found that way and fixed that way. Four more are known and
not yet fixed: a setup interrupted by quitting says nothing about it; restoring
from a backup that holds no keys reports success; a mistyped recovery key shows
an internal error rather than "that key is wrong"; and the restore panel can
stay on "Restoring…" if the session ends mid-restore. None of them can destroy
a key.

**The `.deb` will not install on Ubuntu 24.04** or its derivatives, or the
`.rpm` on Fedora 43 — their Qt is older than Lightning needs. Use the AppImage
or the Flatpak there; both carry their own.
