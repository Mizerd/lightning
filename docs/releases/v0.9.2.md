# Lightning 0.9.2

A repair release, and an unusually blunt one. Everything here is something
0.9.1 broke or left broken, found by the people running it: a Linux client
that would not start, Windows updates that could not install, a settings
panel that froze the app, and history that stopped loading in the rooms
people use most.

## The Linux AppImage starts again

0.9.1 did not launch on a native Wayland session. It aborted during graphics
setup with "EGL not available", before any window appeared.

The AppImage was shipping its own copy of the Wayland client library, older
than the host's, so the system's graphics driver was handed a library it was
not built against and failed to initialise. 0.8.4 had escaped this by
accident: it shipped without a Qt plugin, so Qt refused Wayland entirely and
fell back to XWayland, where the bundled library was never used. Adding that
missing plugin in 0.9.1 exposed a library that had been wrong all along.

The display libraries now come from the host, which is where they belong, and
the packaging refuses to build if they reappear.

Separately, the client no longer exits when no graphics context can be
created. It falls back to software rendering and says so. Video and screen
sharing are slower that way, but starting slowly beats not starting.

Reported by the Arch Linux package maintainer, with a diagnosis precise
enough to confirm in one command.

## Room information no longer freezes the client

Opening a room's information panel could hang the whole application: the
window greyed out, stopped responding and had to be killed.

The tab strip measured whether it fitted using a width that the same layout
pass was still deciding, so the two chased each other. The layout never
finished, the interface thread never came back, and every section drew on top
of the others. The measurement now happens on a control that the answer
cannot move, and it will not flip back and forth on a width that sits exactly
at the boundary.

## History keeps loading in rooms that host calls

Scrolling back in a room used for calls stopped after a page or two. You had
to scroll up repeatedly before older messages appeared.

0.9.1 started hiding the constant stream of call-membership updates, which is
correct, but in a room used for calls those are most of the history. A page
of twenty events could contain nothing to show, and the loader gave up after
four such pages. It now walks through them at the same scale as everything
else that faces the same problem.

In the same area: clicking a reply to jump to an older message did nothing at
all when the target was far enough back. It waited for the view to settle in
a way that never happened while history was still arriving.

## Windows updates can actually install

The update was found and downloaded, the application restarted, and then an
error appeared with the old version still installed. Every Windows package
had its own reason.

* **Setup and MSI** replace the whole installation folder, while the small
  program driving them was running from inside it. Windows will not overwrite
  files that are in use, so the installer stopped. That program is now copied
  out of the way first, with everything it needs.
* **Portable** put its backup inside the folder being replaced, which the
  safety checks refuse before anything moves. The backup is now beside the
  folder.
* A portable copy kept directly on a drive, like `E:\Lightning`, could only
  ever update once.
* An installer that asked for a restart was reported as a refusal, and the
  same update was offered again.
* A partly failed install could report success. The installer now stops and
  says what to do, usually to close Lightning first.
* An installation whose type marker was missing could be treated as portable
  and have its folder moved. That now requires positive proof.

And a failed portable update could delete your settings, session and
encryption keys while reporting that nothing was lost. That one is fixed and
covered by a test that fails on the old code.

**Updating into this release still has to be done by hand.** The program that
performs an update is the one already installed, so a broken 0.9.0 or 0.9.1
cannot repair itself. Download 0.9.2 and install it over your existing copy.
After that, updates work normally.

## Update failures say what happened

Failures were shown as internal codes, so a blocked update read as an unknown
error. Every failure now explains itself in a sentence, with the code kept
underneath for reporting.

## Also in this release

* The account list's remove button works. It flickered under the pointer and
  could not be clicked; its target is also larger now.
* Favourites keep their own section in the room list, which two internal
  checks disagreed with.

## Known limitations

* **Not verified on Windows.** The Windows fixes are made from the code and
  covered by tests, but no one has yet run an update on a Windows machine.
  Reports welcome.
* **macOS remains untested**, as in the last release.
* **A screen share still blurs** when the sending computer is at full load.
  Unchanged from 0.9.1.
* **Switching themes still pauses the window** for about a second.
