# Lightning 0.7.4

Twenty commits since v0.7.3, in two halves. One is Element parity in the
surfaces people actually touch every day — Spaces, the rail, read receipts.
The other is a scrolling-performance round that found four separate real
causes deep in history, and one no-op of my own that a live capture caught
before you had to.

Everything here came out of running the client and measuring it, not from
reading the code and guessing. Two of the round's hypotheses were killed by
measurement after being written down as fact; the notes below say which.

## Scrolling deep in history

The report was simple: scroll up a long way and scrolling gets laggy in both
directions. It turned out to be four unrelated things.

### Every timeline row was making Qt walk the whole tree, every frame

The largest single win, and the cause was not layout. Every `QQuickText` is
born carrying `ItemObservesViewport`, and the only code that clears the flag
is `QQuickText::setText` — which opens with an early return when the text has
not changed. A label bound to a value that is *always empty in the state the
row is created in* therefore keeps the flag forever, and
`QQuickItemPrivate::transformChanged` cannot prune its per-subtree walk while
any descendant observes. Measured on a 1000-row timeline: **3000 observers,
exactly three per row.**

Seven such labels moved into `Loader`s. Observers **3000 → 0**, and per-notch
scroll cost **33.89 ms → 10.39 ms** at 1000 loaded rows. That figure is
offscreen on one machine under software rendering; the felt improvement on a
real desktop is not something a synthetic harness can report.

### One upward gesture was pulling ~120 MB of video

A live capture of a 15-second upward scroll showed fifteen video payloads —
23, 13.5, 12.6, 11.7, 9.5 MB and on down — fetched because every row that
merely *swept through* the on-screen band armed a full-payload prefetch. Each
completion then wrote its temp file synchronously on the GUI thread. The same
capture logged GUI stalls of 333, 369 and 1062 ms.

Speculative media now waits for the view to settle: full-payload prefetch,
the video poster path (which prefetches internally, so gating only the obvious
call site would have left half the traffic) and the audio card. **Thumbnails
are deliberately not gated** — they are small, and they are what you are
actually looking at. The follow-up capture showed the traffic gone and those
stalls with it.

### Jump-to-live now discards the backlog — live-validated

Pressing jump-to-latest from deep in history used to keep every row it had
paginated. It now does what Element classic does: rebuild the timeline at the
live edge and drop the backlog.

Lightning implements no unloading of its own — matrix-sdk already has it, and
this is ordering, verified against the vendored crate rather than assumed.
It refuses more than it accepts (wrong backend, no room, mid-pagination, a
thread panel open, too few rows to be worth a reset), and it commits to
follow-latest only when the dispatch actually succeeded.

This is the one thing in the round with a **live PASS**: the capture reported
`cachedBefore=1083 released=true reloadedItems=19`, and every gesture after it
came back cheap.

### Jump-to-latest glides instead of teleporting

From nearby it animates through the existing scroll engine; beyond four
viewports it stays a jump on purpose, because a twenty-viewport slide at the
engine's ceiling is a second-long blur. Element classic does not animate this
at all — its `scrollToBottom()` is a bare assignment — so this is a deliberate
difference, not parity.

### The sliding row window — and the no-op it shipped as

Frame-time evidence from a real GPU (pagination frames excluded, so it cannot
be confused with loading cost) showed cost tracking *row count*: ~108 loaded
rows gave a 3 ms median frame with 1% over budget; ~916 rows gave 14 ms with
46% over, render grown 14× and polish 5×. So the timeline now bounds how many
rows stay instantiated, keeping a runway below the reader and a margin above,
applied only when scrolling settles.

**It shipped as a permanent no-op and was fixed in the same release.** The
guard read `userScrollActive`, which includes `scrollSettleTimer.running` — and
the window's only caller is that timer's own handler, so the guard could never
pass. Every test covering it called the policy function directly, where the
property reads false: the policy was covered from six directions and the
*trigger* was not covered at all. A live `QSG_RENDER_TIMING` capture is what
exposed it, showing frame work still scaling with total loaded rows (27 ms at
~950 rows) while the window was supposedly active.

Two things came out of that worth stating: a policy test that invokes the
policy function directly proves nothing about whether production reaches it,
so the regression test now drives real wheel events and waits; and the window
had no observability at all, which is how a no-op survived a review gate and
two green sweeps. The scroll trace now reports the window's own state.

**Honest status:** the fix is verified end-to-end offline, and **no production
frame-cost improvement from the window has been measured yet.** The felt
improvement reported during this round belongs to the media gating above.

## Element parity

- **The Space front page is one list.** Joined rooms, joined subspaces and
  rooms you have not joined yet now sit together in a single *Rooms and
  spaces* list, each row stating its own membership, with a *Suggested* tag
  shown only where the hierarchy actually says so. It carries Element's
  selection UI — per-row checkboxes, multi-select removal with one
  confirmation, and a suggest toggle — all gated on your real permission to
  change `m.space.child`. Nothing is applied optimistically.
- **Nested subspaces** are supported end to end: indented in the rail,
  listed and drillable from their parent's front page, and labelled with how
  many rooms they contain when you have not joined them.
- **The rail** opens a Space's overview on a single click; the chevron beside
  the tile expands its most active rooms inline, with a "+N" pill for more.
- **Read receipts are clickable.** The avatar chips open a reader list with
  names, avatars and the time each person read the message. The times were
  already crossing the bridge unused since receipts landed.
- **Space invites** and Space avatar editing, which the front page could not
  do before even though it could already rename a Space.

## From the 0.7.3 Windows tester report

- Changing an emoji skin tone opened **two** menus at once — a right-click on
  a tone-capable tile also reached the message context menu underneath,
  because Qt Quick tap handlers are not exclusive across subtrees. The picker
  is now modal.
- **Copy image** on image rows, straight to the clipboard as both raster and
  original bytes, magic-sniffed rather than trusting a filename. Pasting an
  image already preferred image data; what was missing was the copy side.
- The GIF settings appeared to **reset on every launch**. They were saved
  correctly — the combo boxes were reading their index at creation time,
  before the model had settled.
- Rooms and Spaces without an avatar now fall back to **letter initials**
  instead of a `#` glyph.
- **Replies to an image show a thumbnail**, both in the quote and in the
  composer banner while you type.

## Design

A three-lens audit drove about eighteen consistency fixes across the round
surfaces, message search and the dialogs: empty states and clear buttons where
they were missing, themed ink on controls that had fallen through to Qt's
default style, keycap tokens, text scaling respected in all three search
surfaces, accessible names on history rows, and the remaining dialogs moved
into the same visual dialect as their siblings. The reader-list card is
content-sized, scrolls past its cap, and stays inside the window.

## Voice calls: groundwork only, and deliberately switched off

The signalling lane (MSC2746 `m.call.*`) and a real WebRTC media engine
(GStreamer `webrtcbin`, ICE, DTLS-SRTP, Opus) are both in this release, and a
headless test completes a genuine in-process call. **The button is greyed out
and says "coming soon."**

That is on purpose. No answered call has ever been validated on a real network
or against another client, packaged builds do not yet declare the GStreamer
runtime dependencies, and offering the control would promise something the
release cannot keep. SDP and ICE candidates never cross into the UI layer or
any log.

## Regression net

Both timeline suites that had been failing since the timeline was rebuilt are
green for the first time. One was a real production defect — after a reset,
the presentation gate trusted a `contentHeight` still reporting the outgoing
content's height — and one was a fixture bug, where a live append shifts every
view row by one and the test kept measuring a row that was no longer the event
it meant.

Also added: `LIGHTNING_GUI_STALL_TRACE`, which logs one line per GUI stall
over a threshold with a coarse category, and
`docs/element-interop-checklist.md`, a scripted PASS/FAIL pass for
interoperability.

## Validation

CTest **135 passed / 0 failed of 135** on both the Rust and non-Rust trees —
the first release in a while with nothing carried. cargo test **123 passed /
0 failed / 4 ignored**. Both binaries report `matrix-client 0.7.4`.

One caveat worth stating rather than rounding off:
`nearTopControllerDrivenBatchesCompensateImmediatelyNotChained` failed once in
one non-Rust-tree run during release validation, and passes on re-run (3/3
under CTest, and the full suite green). It is order-dependent — it fails 7 of 8
times when run *alone* and passes in suite order — so it is a fragile test, not
a regression, and it is pre-existing: the row-window work cannot reach it,
because the window refuses below 320 rows and that test loads at most ~130.
Repairing it belongs to its own pass, not to a release.

New suites this round: `reverse-list-proxy-window` (17 cases),
`element-parity-contract`, `space-child-suggest`, `gui-stall-trace`,
`call-media-loopback`, `call-ring-policy`, `call-ui-contract`. Every
regression test for a fixed defect was run against the unfixed tree first;
several were rewritten when they turned out to pass on broken code, including
one whose assertion was deleted outright for exactly that reason.

**Not validated.** Nothing in this release has been checked against Element
for interoperability. The row window's production effect is unmeasured. Voice
calls are unreachable by design. Windows packages remain **unsigned** — the
signed update manifest is the integrity guarantee on every platform.
