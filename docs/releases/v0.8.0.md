# Lightning 0.8.0

Eighty-eight commits since v0.7.6, and the release where **calls started
working**. Not "signalling is implemented" — audio, camera and screen sharing,
in both directions, against Element Call, from a packaged build.

That took most of the round. The rest of it is a second navigation layout, a
large amount of Space and moderation surface, and a long tail of fixes found by
running Lightning on Windows at 150% display scaling and looking at what broke.

## Calls

Lightning joins MatrixRTC group calls and carries real media.

- **Audio, camera and screen sharing**, both directions, interoperating with
  Element Call. Per-participant volume, a spotlight/grid stage, a member
  panel grouped by power level, and a room-list glyph showing where a call is
  already running.
- **Raised hands interoperate with Element.** The wire representation was read
  out of element-call's own source rather than inferred: an `m.reaction`
  annotating the raiser's own `m.call.member` state event.
- **Windows and macOS packages now bundle GStreamer.** Before this, a packaged
  build had no media engine at all and refused every call — correctly, but for
  a packaging reason nobody had noticed. Each artifact now proves itself:
  `--call-media-status` runs from inside the package and reports whether the
  engine loaded.
- **Single-window screen sharing on Windows.** Not just a display — one
  application window. Nothing shippable captures a window
  (`d3d11screencapturesrc` can, but its plugin does not load in this
  toolchain), so Lightning compiles its own capture element. It asks the window
  to render itself rather than cropping the screen, deliberately: cropping
  would share whatever is stacked on top of it, and a share that can leak a
  window you did not choose is not a feature.
- **The share picker** is a grid of live previews with Applications and Screens
  tabs, and it names the owning application — a browser window's caption is
  only its tab title, which tells you nothing about which browser you are about
  to broadcast.

What is live-validated: audio, camera and screen sharing against Element on
Linux, and on a packaged **Windows** build the camera, screen sharing, and
sharing a single window — including its aspect ratio and resizing the window
mid-share. **macOS calling is NOT TESTED.** Closing a shared window while
sharing is implemented and covered by tests but has not been exercised by
hand.

### Three defects worth naming

They are recorded here because each one produced a symptom that pointed
somewhere else entirely.

**The camera sent one frame and froze — and it was never the camera.**
`videorate` starts its output clock at segment start, not at the first buffer.
A publish bin joins a pipeline that has been playing since the call was joined,
and the Windows capture elements stamp buffers with the pipeline's running
time — so a camera switched on three minutes into a call handed `videorate` a
first timestamp of three minutes, and it owed thirty duplicate frames for every
second of that. One picture at full rate, with every counter healthy.

**A shared window arrived sheared.** The capture element advertised a size
range and never learned which size it had negotiated, so it kept producing
buffers at the window's own size while the caps said something smaller.
GStreamer accepts an oversized buffer in silence and reads it at the caps'
stride — every displayed row was half a source row. A window narrower than the
publish ceiling escaped it, which is why File Explorer looked perfect and a
maximised browser did not.

**Every non-16:9 screen share was arriving distorted, on every platform, and
nobody had reported it.** `videoscale` honours a size ceiling by clamping both
axes and signalling the shape as a pixel aspect ratio — which VP8 and RTP do
not carry, so the far end draws the frame at its literal size. A 16:10 display
arrived 11% stretched and an ultrawide 34% squashed. It went unnoticed because
the maintainer's monitors are 16:9.

## Two navigation layouts

The conversation column is now a per-account choice (Settings → Appearance).

- **Classic** — one activity-ordered list. Still the default.
- **Channels** — a Spaces rail choosing between three views: Home, Direct
  Messages, and one view per Space. Rooms are ordered by the Space's own
  `m.space.child` order rather than by activity, subspaces nest at their real
  depth, and a room in two Spaces appears under both.

Spaces can be dragged to reorder, and dropping one onto another makes a
**local folder** — device-only organisation that touches no Matrix state.

## Spaces, moderation and search

- **Space settings** — name, topic, avatar, join rule, canonical alias and the
  full power-level matrix, each gated on the room's real required level.
- **Member power levels**, with the same gating. A room using a custom number
  is shown as that number and saved as that number, never rounded to the
  nearest familiar role.
- **Pinned messages**, read and written through the SDK's own read-modify-send
  so a concurrent change cannot be clobbered.
- **Message search** against the server, and **Discover / Join** for finding
  rooms. Server search covers unencrypted rooms only — the server cannot search
  ciphertext — and every surface says so rather than returning quietly empty.
- **Ignore and report**, through the SDK's own `m.ignored_user_list`.
- **Drafts** — persisted per room, except in encrypted rooms, where they are
  memory-only and do not survive a restart.
- **Presence indicators** on 1:1 DMs, the People list and the member popover.

## Smaller things

- **Rebindable keyboard shortcuts**, including the case that makes them worth
  having: Ctrl+B is Bold inside the composer and toggles the room list
  everywhere else.
- **Hide an image** without moving the timeline — purely local, session-only,
  nothing is redacted or sent.
- **Legacy Matrix SSO** is detected and offered where a server has it.
- **`--log-file PATH`** writes a log on every platform, and **`--console`** now
  works at all — it had never worked in any build, having been parsed in the
  preflight pass and then rejected by Qt's own parser.
- The screenshot-demo mode can photograph Channels and a staged call.

## Fixes

Most of this release's fixes came from running on Windows, where every fixed
pixel size buys two thirds as much at 150% display scaling. Controls drew
through each other because a component reported no implicit width; a shared
screen collapsed to a sliver because the call panel's floor was a flat fraction
of the pane; nameplates never elided; a wrapping paragraph squeezed the buttons
beside it.

Elsewhere: an account switch no longer runs an unbounded profile-fetch loop, the
room list no longer re-syncs itself in a loop, stopping a screen share now
actually stops it at the far end, a message segment no longer forces the lazy
width it is being sized from, and sticky banners no longer replace one person's
picture with another's.

## Known limitations

- **macOS calling is NOT TESTED.** The macOS build is Apple Silicon only,
  macOS 26 or newer, ad-hoc signed and un-notarized.
- **Windows packages are unsigned.** The signed update manifest is the
  integrity guarantee on every platform.
- **The Windows camera runs at 10 fps.** No MJPEG decoder is staged, so the
  camera falls back to raw YUY2, which at 720p saturates USB 2.0. Separate from
  the freeze fixed in this release.
- Linux packages declare no GStreamer runtime dependency; a distribution
  without it keeps the honest refusal rather than failing at call time.
