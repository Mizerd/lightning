# Lightning 0.8.1

A fix release, and a narrow one: **screen sharing works from a packaged Linux
build**. In 0.8.0 it did not, on any Linux format, for two reasons that had
nothing to do with the calling code — both of them packaging, and both invisible
to a from-source build on the same machine.

## Screen sharing on Linux

- **The AppImage shipped `libpipewire` and none of what `libpipewire` loads.**
  It resolves its own SPA plugins and PipeWire modules from directories compiled
  in at build time, and reads its module list from a config file it has no
  built-in fallback for. So a share died at `pw_loop_new` with
  `can't make support.system handle`, after the desktop's picker had already
  returned a node. The bundle now stages `spa-0.2/{support,videoconvert}`, the
  seven required PipeWire modules and `client.conf`, and the AppRun hook points
  at all three. The snap inherits the same AppDir.

- **`pipewiresrc min-buffers` was inherited rather than pinned, and the default
  changed underneath it.** It was 8 through gst-pipewire 1.4.x and is 1 from
  1.6. The element asks for a buffer count RANGE, a compositor caps it low —
  KWin offers at most four — and PipeWire 1.6 added an explicit rejection when
  the two ranges cannot intersect. A bundled 1.4.2 element against a 1.6 daemon
  therefore asked for at least eight where at most four existed, and the daemon
  answered `error alloc buffers: Invalid argument`. It is pinned at 1 now, which
  makes the request independent of both the plugin version and the compositor.

  This also explains a result recorded months ago and misattributed: setting
  `min-buffers=8` had once been tried against an unrelated stall and killed the
  capture outright. That measurement was right; the conclusion drawn from it —
  that the property must never be set — was not.

- **A Linux desktop with no portal now gets a picker** rather than a refusal,
  falling back to X11 capture where that is genuinely possible and refusing
  honestly where it is not. On Wayland without a portal there is no way to
  capture a desktop, and Lightning says so instead of publishing a black
  rectangle.

## Emoji

- **Emoji rendered as monochrome outlines or tofu in packaged builds** while
  looking correct from source, on the same machine with the same fonts. Qt's
  automatic per-character fallback is version-dependent: Qt 6.8 prefers a
  monochrome font that claims the codepoint where Qt 6.11 picks the colour one.
  The face is now named explicitly, resolved against fonts the host actually
  has.
- **Typed emoji get the face too.** The composer is mixed text, so the emoji
  runs are formatted per-range through the highlighter already attached to that
  document — the words around them keep the UI face.
- **They are also much bigger**: a 30 px glyph in a 46 px cell, up from 19 in 32.
- The face had to be named at **four separate surfaces** — the picker, the
  composer, a sent message, and a room-list preview — and fixing each one
  revealed the next, because none is reachable from the others.

## Emoji, links and the composer

- **Links now open from the AppImage.** `xdg-open` inherits the app's
  environment, and inside an AppImage that points at the bundle — so the
  browser loaded the bundle's glib ahead of the host's and never started, with
  no error anywhere. The spawned child now gets the session's own loader path
  back, and every variable pointing into a mount that does not outlive
  Lightning is stripped.
- **Typed emoji get the colour face too.** Naming a family fixes a label that
  holds only an emoji; the composer holds mixed text, where naming one family
  would render the words in it. It is handed a font carrying the UI face with
  the emoji face behind it, which is real per-character fallback.
- **A media key is no longer recorded as delivered when it reached nobody.**
  Three cases wrote a false success — an empty target set, a send the backend
  refused outright, and a failed send result — and each made the one retry path
  see "nothing changed" and skip the redistribution the failure was the reason
  for. The distribution log now carries the peer and unresolved counts, because
  "reached nobody with a peer present" and "reached nobody because nobody is
  there" were indistinguishable.

## Navigation

- **Clicking a person in Direct Messages no longer threw you back to Home.**
  The rail's selection carries tab sentinels for Direct Messages and for the
  rooms in no Space, and those are not rooms — so the check that drops a Space
  you have left was clearing them on every rebuild of the space list, which
  opening a conversation causes.

## Reply quotes

- **A quote was cut at 80 characters, mid-word, with nothing to mark it.** That
  budget belongs to a room-list row, not to a quote in a timeline that can be
  1500 px wide. It is 320 now, marks its own truncation, and the label elides to
  the width actually available.
- **A quote showed a username where the timeline showed a display name.** The
  reply's sender is resolved from the replied-to event's own profile now, and
  the quote takes that person's identity colour, matching their messages.
- **Stray accent-coloured text over words that were not mentions.** Mention
  highlight ranges can go stale — the composer's text is replaced wholesale by
  an edit or a draft restore. A range is now offered only while the text it
  names is still that mention.

## Known limitations

- **AppImage, rpm and Flatpak have been exercised end to end** — audio, camera
  and screen sharing, against a real homeserver. **deb has not**, and is
  believed to work by inference from rpm: both declare GStreamer as a
  dependency rather than bundling it, so both inherit a stack the distribution
  made self-consistent. Treat that as reasoning, not as a test.
- **A first join can still need a retry.** The membership snapshot is sometimes
  empty at the moment the media key is first distributed, and the key then
  reaches nobody; leaving and rejoining the call fixes it. This is pre-existing
  rather than new in 0.8.1, and this release makes it visible in the log rather
  than silent — the underlying cause is not yet fixed.
- **macOS calling remains NOT TESTED.**
- The Windows camera still negotiates at 10 fps; the cause is a missing JPEG
  plugin in the staged set and is unchanged in this release.
