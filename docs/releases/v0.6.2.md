# Lightning 0.6.2

A correctness and polish release focused on how rooms load, how people and
media render, encrypted-history recovery, and day-to-day interaction speed.

## Timeline stability

- Opening a room no longer presents a half-built snapshot that visibly
  rebuilds: the timeline appears once it is coherent, positioned at the
  latest message, behind a quiet loading surface.
- Scroll anchoring is stable in both directions. While you follow the
  newest message, late-loading images, link previews, decryption updates,
  and profile resolution keep the newest message pinned; while you read
  older history, the message under your cursor holds its position as
  content above and below it finishes loading.
- In-place event updates no longer relayout the entire timeline.

## Loading placeholders and typed media

- Every deferred content class reserves its final geometry with a
  theme-aware loading skeleton (subtle shimmer, reduced-motion aware,
  animating only while visible): images, GIFs, link previews, and
  encrypted messages awaiting keys.
- Videos now render a real thumbnail card with duration and a play badge;
  audio and voice messages get a compact fixed row; stickers render with
  their transparency preserved. Room previews and notifications name these
  types correctly.

## People

- Sender names and avatars are consistent across the timeline, grouped
  messages, threads, and the member list. Lightning now hydrates room
  membership through the Matrix SDK, so historical senders resolve their
  real profiles instead of showing raw Matrix IDs and letter fallbacks.
- When no display name exists anywhere, the visible label falls back to
  the user's localpart — the full Matrix ID stays available in tooltips
  and details.
- Avatars have explicit loading/ready/missing/failed states. Transparent
  avatar images now render over the actual surface — never over the
  generated fallback colour — and fallback colours are keyed to the stable
  user id, so a resolved name never recolours a person.

## Encrypted history after verification

- Verifying Lightning from an already trusted session now runs the
  standards-based bootstrap end to end: the SDK requests the missing
  secrets from your verified session, unlocks key backup when the secret
  arrives, downloads the backed-up room keys in one pass, and decrypts
  history in place. Settings → Privacy & security shows live progress
  ("requesting keys", "restoring encrypted history", ready), and manual
  recovery-key entry remains available as the fallback.
- Live interoperability of this flow against another client/session should
  still be verified in your own environment; the mechanics are SDK-owned
  and covered by automated state tests.

## Interaction fixes

- Account switching works repeatedly in both directions (A → B → A → B):
  the switcher no longer traps you on the second account.
- Favorite GIFs send the exact GIF you clicked — never the first Trending
  item.
- The emoji picker opens immediately and switches categories instantly.
- Launching with a signed-in account never flashes the login form; a
  branded restoration surface shows until your session is ready.
- Message actions (three-dot menu, right-click) use the redesigned
  Lightning popover with icons, grouping, keyboard navigation, and a
  clearly distinct destructive Delete. A View profile action was added.

## Appearance

- Settings → Appearance gains a Font section with five bundled, openly
  licensed UI families: Manrope (default), Inter, IBM Plex Sans,
  Source Sans 3, and Plus Jakarta Sans — previewed in place, applied
  live across the interface, and remembered per account. Code, Matrix
  IDs, icons, and emoji keep their dedicated fonts.

## Also in this release

- GIF provider configuration is discovered by the app itself (environment,
  local env file, or embedded release keys) and re-checked when the picker
  opens.
- Settings is a full application view; the right panel state is
  authoritative (closing a thread returns to no panel).
- Shared themed controls replace the last native-styled menus.
